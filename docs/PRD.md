# 产品需求文档 (PRD)

## 1. 项目概述

| 字段 | 内容 |
|------|------|
| 项目名称 | MOURO (Multi-Objective Urban Route Optimization) |
| 一句话描述 | 考虑应急程度与客户需求的城市配送多目标路径优化系统 |
| 目标用户 | 毕业设计答辩评委、物流调度研究人员 |
| 项目性质 | 南京林业大学本科毕业设计 |

## 2. 核心目标（MVP 边界）

| 编号 | 预期研究成果 | MVP 状态 |
|------|-------------|---------|
| G1 | 提出一种改进的混合蚁群算法（单目标→多目标），攻克多目标协同优化难题 | 必须完成 |
| G2 | 构建一个精细化路径优化模型，实现应急与需求因素的量化集成 | 必须完成 |
| G3 | 开发一个城市配送仿真系统，提供从计算到可视化的全流程解决方案 | 必须完成 |
| G4 | 达成 80% 以上算法准确率，验证方案的有效性与优越性 | 必须完成 |

**G4 准确率计算方法（锚点校验）：**

在三个锚点 λ=[1,0,0]、[0,1,0]、[0,0,1] 下分别运行改进 ACO 和 OR-Tools 精确求解，按主目标计算 Gap：

$$Gap_k = \frac{|F_k^{ACO} - F_k^{exact}|}{F_k^{exact}} \times 100\%$$

$$准确率_k = 1 - Gap_k$$

三个锚点的准确率取平均值，要求 $\overline{准确率} > 80\%$。

## 3. 数学模型定义

### 3.1 目标函数

**目标1：最小化纯经济成本 (F1)**

$$F1 = \sum_{k=1}^{K} C_{fixed} + \sum_{k=1}^{K} \sum_{(i,j) \in Route_k} d_{ij} \times C_{per\_km}$$

- $K$：使用的车辆总数
- $C_{fixed}$：单辆车固定使用成本
- $d_{ij}$：节点 i 到节点 j 的行驶距离
- $C_{per\_km}$：单位距离成本
- 包含回程（最后一个客户 → 配送中心）的距离

**目标2：最小化加权完工时间 (F2')**

$$F2' = \sum_{i=1}^{N} \omega_{ei} \times t_{arrive,i}$$

- $\omega_{ei}$：客户 i 的应急权重
- $t_{arrive,i}$：客户 i 的到达时刻（从 T=0 起算的绝对时间）
- 不包含车辆回程时间

**目标3：最小化时间窗惩罚成本 (F3)**

$$F3 = \sum_{i=1}^{N} P_i(t)$$

$$P_i(t) = \alpha_i \cdot \max(ET_i - t, 0) + \beta_i \cdot \max(t - LT_i, 0)$$

- $\alpha_i$：客户 i 的早到惩罚系数
- $\beta_i$：客户 i 的迟到惩罚系数

### 3.2 归一化方案

采用 Min-Max 归一化，边界在算法迭代过程中动态更新：

$$F_k^* = \frac{F_k - F_k^{min}}{F_k^{max} - F_k^{min}}$$

- $F_k^{min}$、$F_k^{max}$：目标 k 在当前已知解中的最优值和最差值
- 归一化后 $F_k^* \in [0, 1]$
- **除零保护：** 当 $F_k^{max} = F_k^{min}$ 时，令 $F_k^* = 0$（所有解在该目标上无差异，不影响排序）

### 3.3 综合目标函数

$$\min Z = \lambda_1 F1^* + \lambda_2 F2'^* + \lambda_3 F3^*$$

- $\lambda_1 + \lambda_2 + \lambda_3 = 1$
- 三个目标均为最小化方向

**λ 组合方案：**

| 用途 | 组合 | λ₁ | λ₂ | λ₃ |
|------|------|-----|-----|-----|
| 业务-成本导向 | 固定 | 0.70 | 0.15 | 0.15 |
| 业务-时效导向 | 固定 | 0.15 | 0.70 | 0.15 |
| 业务-均衡型 | 固定 | 0.33 | 0.33 | 0.34 |
| 实验-Pareto采样 | 步长0.2均匀采样 | 共21组 | — | — |

### 3.4 应急等级与惩罚系数联动规则

| 应急等级 | 订单类型 | ω_ei | 时间窗类型 | 早到行为 |
|---------|---------|------|-----------|---------|
| 高 | 医疗应急物资 | 2.0 | 硬时间窗 | 原地等待至 ET_i |
| 中 | 生鲜冷链产品 | 1.5 | 紧软时间窗 | 立即服务，产生早到惩罚 |
| 低 | 普通电商包裹 | 1.0 | 宽软时间窗 | 立即服务，产生早到惩罚 |

**惩罚系数联动公式：**

$$\alpha_i = \alpha_{base} \times \omega_{ei}$$
$$\beta_i = \beta_{base} \times \omega_{ei}$$

- $\beta_{base} > \alpha_{base}$（迟到惩罚大于早到惩罚）

## 4. 约束体系

### 4.1 车辆约束

| 约束项 | 规则 |
|--------|------|
| 车队类型 | 同质车队（所有车辆型号相同） |
| 载重上限 | 固定值 Q（用户可配置，默认 1000kg） |
| 车辆数量 | 无限供应，算法自动决定使用数量 |
| 容量约束 | 单条路线所服务客户的 demand_weight 总和 ≤ Q |
| 超载处理 | 蚂蚁返回配送中心，开启新路线（新车） |

### 4.2 时间约束

| 约束项 | 规则 |
|--------|------|
| 发车时刻 | 所有车辆统一在 T=0 出发 |
| 配送中心时间窗 | [0, T_max] |
| T_max 来源（基准模式） | 读取 Solomon 文件 Node 0 的 late_time |
| T_max 来源（仿真模式） | 前端用户输入（默认 480 分钟） |
| 回程约束 | 车辆返回配送中心时间 t_return ≤ T_max |

### 4.3 时间窗规则

**硬时间窗（医疗，ω=2.0）：**

| 场景 | 行为 |
|------|------|
| 早到（t < ET_i） | 原地等待，服务开始时间 = ET_i，不产生惩罚，但浪费时间 |
| 准时（ET_i ≤ t ≤ LT_i） | 正常服务 |
| 迟到（t > LT_i） | 路径不可行，转移概率 P_ijk = 0 |

**软时间窗（生鲜 ω=1.5 / 普通 ω=1.0）：**

| 场景 | 行为 |
|------|------|
| 早到（t < ET_i） | 立即服务，产生早到惩罚 α_i·(ET_i - t) 计入 F3 |
| 准时（ET_i ≤ t ≤ LT_i） | 正常服务，无惩罚 |
| 迟到（t > LT_i） | 允许服务，产生迟到惩罚 β_i·(t - LT_i) 计入 F3 |

**服务时间计算：**

- 硬时间窗早到：t_leave = ET_i + service_time
- 软时间窗早到：t_leave = t + service_time
- 准时/迟到：t_leave = t + service_time

### 4.4 预检机制

算法运行前对所有硬时间窗客户执行可达性检查：

```
对于每个硬时间窗客户 i：
    t_min_arrive = travel_time(Depot, i)
    如果 t_min_arrive > LT_i：
        从 customer_list 中剔除客户 i
        加入 unreachable_orders 列表
        前端弹出红色告警
```

## 6. 数据方案

### 6.1 基准模式（Solomon 算例）

| 项目 | 说明 |
|------|------|
| 数据来源 | Solomon VRPTW 标准算例库 |
| 选用实例 | C101、C201、R101、R201、RC101、RC201 |
| 距离计算 | 欧氏距离 $d_{ij} = \sqrt{(x_i-x_j)^2+(y_i-y_j)^2}$ |
| 行驶时间 | $t_{ij} = d_{ij}$（速度=1，距离矩阵即时间矩阵） |
| 矩阵类型 | 对称矩阵 |
| T_max | 读取 Node 0 的 late_time 字段 |

**应急等级映射规则（基于时间窗宽度百分位）：**

```
1. 计算所有客户的时间窗宽度 W_i = LT_i - ET_i
2. 按 W_i 升序排序
3. 前 10%（W_i 最小）→ 医疗（ω=2.0，硬时间窗）
4. 第 11%~30%          → 生鲜（ω=1.5，紧软时间窗）
5. 剩余 70%            → 普通（ω=1.0，宽软时间窗）
```

### 6.2 仿真模式（首尔 ACVRP 数据集）

| 项目 | 说明 |
|------|------|
| 数据来源 | [Mendeley ACVRP 数据集](https://data.mendeley.com/datasets/5db8mtw4wg/1) |
| 城市 | 韩国首尔 |
| 矩阵类型 | 非对称矩阵（真实路网） |
| 地图展示 | Leaflet + OpenStreetMap |

**缺失字段生成策略：**

| 字段 | 生成方法 |
|------|---------|
| 应急等级 | 按用户设定比例（默认 10/20/70）随机洗牌分配 |
| 需求量 q_i | 截断正态分布 N(50, 20)，范围 [10, 200] kg |
| 服务时间 s_i | s_i = 5 + 0.1 × q_i（分钟） |
| ET_i | t_{0,i} + random(0, 60)，其中 t_{0,i} 为仓库到客户最短行驶时间 |
| LT_i | ET_i + W_i |

**时间窗宽度 W_i 按应急等级联动：**

| 应急等级 | W_i 范围 |
|---------|---------|
| 医疗（ω=2.0） | [15, 30] 分钟 |
| 生鲜（ω=1.5） | [60, 120] 分钟 |
| 普通（ω=1.0） | [240, 480] 分钟 |

## 7. 不包含在本期范围内的内容

| 排除项 | 原因 |
|--------|------|
| 多配送中心（MDVRP） | 复杂度过高，偏离核心创新点 |
| 异质车队 | 状态空间爆炸，非本科级别 |
| 动态发车时间 | 引入连续变量优化维度，复杂度过高 |
| 实时交通数据接入 | 超出毕设范围 |
| 多用户系统与权限管理 | 非必要，单账号即可 |
| 云服务器部署 | 本地演示即可 |
| 原生 MOACO（外部存档集+拥挤度） | 用加权和+多组λ替代 |
| 跨车路线交换（Inter-route） | 仅做路线内 2-opt |
| 订单溢出/外包机制 | 假设车辆无限供应 |
